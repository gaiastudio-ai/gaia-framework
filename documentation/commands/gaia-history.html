/gaia-history

user-facing
Category:
Sprint Management
Lifecycle phase:
Any
Arguments:
[--last-n N]

What it does

/gaia-history displays a read-only project-history dashboard with three views:

  • Velocity trend -- story points completed across the last N closed sprints.
  • Estimate accuracy -- estimated story points compared to measured agent throughput (median minutes per story and minutes per point), derived from lifecycle-event timestamps.
  • Recurring-finding patterns -- themes that appear in the "What Could Improve" sections of more than one retrospective.

This is a read-only command. It does not write, edit, or delete any artifact, config, or state file. Throughput is measured in wall-clock between story state transitions (how fast the agent worked), not calendar-day velocity. The median is used instead of the mean to resist outliers.

When to use it

  • You are planning a new sprint and want to calibrate estimates against historical throughput.
  • You want to see whether recurring problems from past retrospectives have been addressed.
  • You want a velocity trend to share during a review or retrospective.

Prerequisites

  • At least one closed sprint. The dashboard degrades gracefully with no data -- it shows empty-history placeholders rather than erroring -- but meaningful output requires at least one closed sprint in the archive.

How to invoke

/gaia-history
/gaia-history --last-n 5

What it does step by step

  1. Render the history dashboard Runs the renderer script against the sprint archive, retrospective documents, and lifecycle-events log. Emits a Markdown report with Velocity Trend, Estimate Accuracy, and Recurring Finding Patterns sections.
  2. Surface the throughput caveat Reminds you that the measured throughput is agent-native: it reflects wall-clock between story state transitions, not points-per-calendar-day. A stable minutes-per-point across sprints signals that estimates track measured throughput.

Outputs

Example session

> /gaia-history --last-n 3

## Velocity Trend (last 3 sprints)

| Sprint   | Stories | Points | Duration |
|----------|---------|--------|----------|
| sprint-5 | 8/8     | 42     | 1d 4h    |
| sprint-6 | 11/11   | 58     | 1d 8h    |
| sprint-7 | 9/9     | 50     | 1d 2h    |

## Estimate Accuracy

Median throughput: 18 min/story, 3.2 min/point
Trend: stable (within 15% across last 3 sprints)

## Recurring Finding Patterns

  1. "Flaky tests in CI" (appeared in 2/3 retros)
  2. "Review turnaround slow" (appeared in 2/3 retros)

Note: measured throughput is agent-native -- wall-clock between story state
transitions, not points-per-calendar-day.

What to run next

  • /gaia-sprint-plan -- use the velocity trend to calibrate the next sprint's capacity.
  • /gaia-retro -- run a retrospective to generate new findings.
  • /gaia-sprint-status -- view the current sprint's progress.

Troubleshooting

No closed sprints found

The sprint archive directory is empty. Close at least one sprint via /gaia-sprint-close to populate it.

Throughput shows "no data"

The lifecycle-events log is missing or contains no state_transition events. Throughput is derived from timestamps in this log -- if the project predates lifecycle-event tracking, the section will show a placeholder.

Recurring patterns section empty

No retrospective documents exist, or none have a "What Could Improve" section with overlapping themes.
