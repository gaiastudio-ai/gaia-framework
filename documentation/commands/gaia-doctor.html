/gaia-doctor

user-facing
Category:
Getting Started
Lifecycle phase:
2 -- Discovery
Arguments:
[--install [--docker|--no-docker]] [--json] [--stack <name>]

What it does

/gaia-doctor scans your project for declared stacks and checks which deterministic tools (jq, yq, grype, cdxgen, vulture, etc.) are installed on the host. It produces a per-stack readiness table, a scan-tier verdict, and a copy-pasteable install plan for anything missing. The command is read-only by default -- it probes the host environment without modifying project files or installing anything.

Three scan tiers exist:

  • Tier 0 (LLM-only) -- always achievable; no external tools required.
  • Tier 1 (pure-pip / npm / static-binary) -- lightweight tools that are easy to install on any host.
  • Tier 2 (heavy/native or containerized) -- tools like grype, syft, spotbugs, mobsf that typically require Homebrew or Docker.

When to use it

  • You are onboarding a project and want to know which tools are missing before running /gaia-brownfield.
  • A scan degraded to LLM-only heuristics and you want to see which tools would restore deterministic coverage.
  • You want a machine-readable readiness report for CI integration (--json).

Prerequisites

  • None required. If .gaia/config/project-config.yaml is absent, the command falls back to signal-based stack detection. It never halts on a missing config.

How to invoke

/gaia-doctor
/gaia-doctor --stack python
/gaia-doctor --install
/gaia-doctor --install --docker
/gaia-doctor --json

What it does step by step

  1. Detect stacks Reads stacks[].language from .gaia/config/project-config.yaml. If --stack <name> is provided, uses that single value. If no config exists, falls back to signal-based auto-detection.
  2. Load readiness registry Reads the bundled tool-readiness.json registry and filters entries whose applies_to_stacks intersects the detected stack set.
  3. Probe each applicable tool Runs each tool's probe command (typically command -v <bin>) and records present, missing, or warning plus the resolved version.
  4. Render readiness table Emits a per-stack table with four possible states per tool: present, missing (with install command), not-applicable, or environment warning.
  5. Emit tier verdict Computes the achievable scan tier from the present/missing tool set and reports it.
  6. Install (opt-in only) When --install is passed, prompts before each missing tool and runs the registry's install command for the detected OS. Re-probes after installation to confirm. Without --install, emits the install plan as copy-pasteable shell commands.

Inputs

InputSourceDescription
--stack <name>Command argument (optional)Limit the probe to a single named stack instead of auto-detecting.
--installFlag (optional)Enter interactive install mode. Prompts per tool before installing.
--dockerFlag (optional, with --install)Pull the bundled OCI image instead of installing Tier 2 tools individually.
--no-dockerFlag (optional, with --install)Force per-tool host installs even when the project runner is set to docker.
--jsonFlag (optional)Emit machine-readable JSON output for CI integration.

Outputs

OutputLocationDescription
Readiness tableConsole outputPer-stack table showing present/missing/warning/not-applicable status for each tool.
Tier verdictConsole outputThe achievable scan tier (0, 1, or 2) with a reason summary.
Install planConsole outputCopy-pasteable shell commands grouped by package manager (when --install is not used).

Example session

> /gaia-doctor

GAIA deterministic tools -- readiness for stack: python
  ✓ jq, yq, python3            (core, present)
  ✗ grype          CVE scan of dependencies      →  brew install grype
  ✗ cdxgen         SBOM generation               →  npm i -g @cyclonedx/cdxgen
  ✗ vulture        Python dead-code              →  pip install vulture
  – spotbugs       JVM dead-code                 (not needed: no JVM stack)

Result: 1/3 applicable tools available. CVE + SBOM + dead-code will fall
back to LLM heuristics. Run /gaia-doctor --install to fix, or proceed.

Achievable scan tier: TIER 0 (LLM-only)

What to run next

  • /gaia-brownfield -- run the brownfield scanner now that you know which tools are available.
  • /gaia-config-brownfield -- configure the brownfield section (runner, tier, grype toggle) before scanning.

Troubleshooting

bash 3.2 detected

The probe found macOS's built-in Bash 3.2. Some orchestration features require Bash 4.0+. Install a newer version via brew install bash.

No stacks detected

Neither the config file nor signal detection found any stacks. Create a project configuration with /gaia-init or pass --stack <name> explicitly.

Docker pull fails

When using --install --docker, ensure Docker is running and you have access to ghcr.io. Check your Docker daemon status and any proxy/firewall configuration.
